# 📝 考试日历 · 报名 考试 成绩一览

> 考研、国考、四六级、教资、会计、注会、法考、软考、一建等 20 门全国统一考试的报名、考试、出成绩时间，带截止倒计时，可以一键加到手机日历

**🌐 在线访问：[https://climb0516.github.io/exam-calendar/](https://climb0516.github.io/exam-calendar/)**

---

## 功能

- **概览**：正在报名的考试（截止倒计时 + 进度条 + 报名入口）、下一场考试、下一次出成绩、下一个开始报名；接下来 45 天的日程；官网近 7 天的新公告
- **时间线**：按月份排列所有报名、准考证、考试、成绩节点，可显示已过去的
- **考试一览**：按类别（升学、公务员、语言、计算机、教师、财会、法律、职业资格）列出每门考试各场次的日程，附官网最新公告和报名入口
- **最新公告**：各考试官网的公告每天抓取，近 7 天新出现的标「新」；国考、注会、法考的官网抓不到，用新闻补充
- **我关注的考试**：点选标星，可以只看关注的（保存在本机浏览器）
- **加到手机日历**：下载 `.ics` 文件（关注的考试；没关注就是全部），导入 iPhone / 安卓日历；报名截止前一天、考试前一天会提醒
- 全文搜索（`⌘K` / `Ctrl K`），深浅色切换，手机适配

## 数据

| 文件 | 内容 | 更新方式 |
|---|---|---|
| `exams.json` | 各考试各场次的报名、考试、成绩日期；每个日期标 `official`（附官方来源链接）或 `estimate`（官方还没公布，按往年惯例推算，页面标「预估」） | **人工维护**，各考试发布报名公告、人社部发布年度计划时更新 |
| `data.json` | 官网最新公告 | `scraper.py` 每天自动抓取 |

公告来源：研招网、四六级 / 教资 / 计算机等级官网（教育部教育考试院）、中国人事考试网、会计资格评价网、软考官网；国考、注册会计师、法考用 Google / Bing 新闻。人事考试网、会计资格评价网、软考官网对 GitHub Actions 的海外 IP 返回 405 或超时，在 Actions 上抓不到，另用新闻补充（会计职称、职业资格、软考三组）。

**注意**：教资、会计、软考、职业资格等按省报名的考试，各省时间不同，`exams.json` 里写的是全国大致区间，以本省公告为准。

### 更新 exams.json

每门考试的结构：

```
{
  "id": "kaoyan", "name": "全国硕士研究生招生考试", "short": "考研", "category": "升学",
  "site": "https://yz.chsi.com.cn/", "keywords": "研考|硕士研究生",
  "sessions": [
    { "label": "2027 年度", "events": [
      { "type": "报名", "start": "2026-10-15", "end": "2026-10-24", "status": "official", "source": "https://...", "note": "" }
    ] }
  ]
}
```

- `type`：预报名、报名、确认、准考证、考试、成绩
- `keywords`：官网公告标题命中就挂到这门考试下（正则）
- 官网出现新公告（页面标「新」）时，打开公告核对日期，把对应的 `estimate` 改成 `official` 并填 `source`

## 技术架构

```
GitHub Actions（定时：每天北京时间 08:30 / 手动 dispatch / push 修改 scraper.py 或 workflow）
  ↓ python scraper.py（Python 3.12，只用标准库，无需安装依赖）
  ↓ 线程池（6 并发）抓取 7 个考试官网首页公告 + 6 组新闻（Google News RSS + Bing News RSS）
  ↓ 关键词过滤 → 与上一份 data.json 按 URL 合并（记录 first_seen，失败来源沿用旧数据）→ 只保留近 120 天
  ↓ 写入 data.json，git commit + push（updated 每次都变，保证每次都有提交）
       ↓
GitHub Pages（index.html，纯静态）
  ↓ 浏览器同时 fetch exams.json（人工维护的考试日程）+ data.json（公告）
  ↓ 概览 / 时间线 / 考试一览 / 最新公告 四个视图；倒计时、.ics 日历文件都在浏览器里生成
  ↓ 详情抽屉 #/item/exam|notice/<id> + 列表页 #/list/notices、#/list/timeline（通用组件 kit）
```

**增删来源**：
- 新增官网：在 `SITES` 里加一项 `{"key", "name", "url", "include", "exclude"}`（include / exclude 为正则），爬虫会解析该页面所有链接；
- 新增新闻组：在 `NEWS` 里加 `key: [搜索词...]`，同时在 `NEWS_MUST` 里给出标题必须命中的正则；
- 删除：从对应字典 / 列表中移除即可，前端按 `sources` 动态显示。

## 数据处理规则

**官网公告（`site_notices()`）**
- 用正则提取页面所有 `<a href>...</a>`；若 `title` 属性比链接文字更长则用 `title` 属性，并去掉断行带出的 HTML 碎片
- 过滤：标题长度 < 10 的丢弃；必须命中该站 `include` 正则，且不能命中 `exclude` 正则（如研招网排除 `复试|调剂|院校|大学|学院|学位|培养|导师|博士|推免|推荐免试|拟录取|名单|章程|拟招生`）
- 去重：同一页面内按完整 URL 去重；`javascript:` 链接丢弃
- 发布日期 `find_date()`：在链接后面 300 字以内的文字或 URL 里找 `2026-09-27` / `2026.09.27` / `2026年9月27日`，或 URL 里的 8 位 `20260927`；晚于明天的日期视为无效
- 一条都没匹配到时抛错，按「抓取失败」处理

**新闻（`news()`）**
- 每个搜索词同时查 Google News 和 Bing News；Google 标题末尾的「 - 来源」去掉，Bing 链接解析出真实 `url`，并取 `<description>` 前 300 字作摘要
- 只保留近 `NEWS_DAYS = 30` 天的
- 标题必须命中 `NEWS_MUST[分组]`（如国考 `国考|国家公务员|中央机关`、会计 `会计.{0,4}(?:职称|资格)`）
- 排除 `NEWS_EXCLUDE`：`培训|课程|网课|押题|真题|答案|机构|班|广告|怎么备考|备考攻略|攻略|经验|教育提醒|教育网`
- `NEWS_SKIP`：「职业资格」组排除 `法律职业资格|法考`，避免和法考组混在一起
- 去重：标题只留中文、字母、数字后取前 18 个字符作 key；重复时若后到的 Bing 有摘要，就补给先到的 Google 那条
- 按日期倒序，每组最多 12 条

**合并与保留（`main()`）**
- 读取上一份 `data.json`，按 `url` 建索引
- 某来源本次失败：沿用上一次该来源的条目，`sources[key].stale = true`（页面右侧标「旧数据」）
- `first_seen`：老条目沿用原值；新条目记为今天；**第一次运行**（没有旧数据）时留空，避免全部被标「新」
- 只保留 `date`（没有则用 `first_seen`）在近 `KEEP_DAYS = 120` 天内的公告，按日期倒序

**前端识别（`index.html` 的 `prep()`）**
- 公告挂到哪门考试：用 `exams.json` 里每门考试的 `keywords` 正则（没有则用页面内置 `KW` 映射或简称）匹配公告标题
- 「新」标记：`first_seen` 在 7 天内，或发布日期在 3 天内
- 公告 id：URL 的 djb2 短哈希（base36），同一条公告每次抓取都一样，可用于分享链接

## 数据结构

**data.json**（爬虫生成）

```
{
  "updated": "2026-10-22T12:49:00+08:00",   // 本次运行时间（北京时间），每次都变
  "today":   "2026-10-22",
  "sources": {
    "yz": { "ok": true, "stale": false, "error": "", "count": 14, "name": "研招网" },
    ...                                        // 7 个官网 key + 6 个新闻组 key，新闻组 name 为「新闻」
  },
  "notices": [ ... ]
}
```

单条公告：

```
{
  "site":       "guokao",              // 来源 key（官网 key 或新闻组 key）
  "source":     "搜狐",                 // 官网名，新闻则为媒体名（缺省「新闻」）
  "title":      "...",
  "url":        "https://...",
  "date":       "2026-10-22",           // 发布日期，官网可能为空
  "first_seen": "2026-10-22",           // 首次抓到的日期，首次运行时为空
  "news":       true,                   // 仅新闻条目有
  "desc":       "..."                   // 仅部分新闻条目有（Bing 摘要）
}
```

**exams.json**（人工维护）：顶层 `{ "note": "数据说明", "exams": [...] }`，共 20 门考试；单门考试结构见上文「更新 exams.json」。`category` 取值：升学、公务员、语言、计算机、教师、财会、法律、职业资格；事件 `status` 为 `official` 或 `estimate`。

**.ics 日历文件**：不落地在仓库里，由前端 `downloadICS()` 在浏览器生成下载（`考试日历.ics` 或 `考试日历-<简称>.ics`）。只导出未过去的事件；考试日提前 1 天提醒（`TRIGGER:-P1D`）；报名 / 预报名 / 确认类事件额外生成一条「⚠️ XX 截止」事件，截止前 1 天提醒。

## 前端

**详情抽屉 + 列表页（通用组件 kit）**：电脑上从右侧滑出，手机上从底部升起。地址写在 hash 里，分享链接可以直接打开对应详情；条目已过期或不在当前数据里（比如链接来自旧数据）时，弹出「这条内容已不在当前数据里」的提示。

| 地址 | 内容 |
|------|------|
| `#/item/exam/<考试 id>` | 考试详情：要点（简称、分类、下一场考试、相关公告数）、全部时间安排（官方 / 预估）、相关公告、说明；可关注、导出这门考试的 .ics |
| `#/item/notice/<公告 id>` | 公告详情：摘要、说明、所属考试、同考试其它公告 |
| `#/list/notices` | 全部公告列表，支持 `?kind=official\|news`、`?exam=<考试 id>`、`?src=<来源>` 筛选 |
| `#/list/timeline` | 全部日程列表，支持 `?type=<报名\|考试\|成绩…>`、`?past=1`（含已过去的） |

列表页每页 30 条（`LPAGE`），可「加载更多」。

**项目特有功能**
- 四个视图：概览 `home` / 时间线 `timeline` / 考试一览 `exams` / 最新公告 `notices`，选中的视图记在本机
- 倒计时与阶段（未开始 / 进行中 / 已过去）按北京时间在前端计算；概览展示「接下来 45 天」日程、近 7 天新公告
- 关注的考试、「只看关注的」开关、视图、主题保存在 `localStorage`（键前缀 `ec:`）
- 顶部「公告更新于 X 分钟前」根据 `data.json` 的 `updated` 每分钟刷新

## 本地运行

```
python3 scraper.py          # 生成 / 更新 data.json，只用标准库，无需 pip 安装
python3 -m http.server      # 浏览器打开 http://localhost:8000
```

- 依赖：Python 3（Actions 上用 3.12），无第三方库

## 自动更新机制

工作流：`.github/workflows/scrape.yml`

| 触发方式 | 时机 |
|---------|------|
| GitHub Actions 定时任务 | 每天 08:30 北京时间（cron `30 0 * * *`，UTC 00:30） |
| push 到 main 分支 | 仅当改动了 `scraper.py` 或 `.github/workflows/scrape.yml` |
| GitHub Actions 手动 dispatch | 按需触发 |
| 人工修改 `exams.json` 并 push | 不触发爬虫，GitHub Pages 重新部署后页面即读到新日程 |

- 运行后只 `git add data.json`，提交信息 `data: update <北京时间>`；`concurrency: scrape` 保证不会两次同时运行
- **心跳**：`data.json` 的 `updated` 字段每次运行都会变化，所以每次都有提交。GitHub 会在仓库 60 天无提交时自动停用定时任务，这里每天的提交能让仓库保持活跃；若仍被停用，需在 Actions 页面手动重新启用
